# Known limitations and unverified areas

## Platform / host verification
1. **Windows and Ableton Live were never built or tested.** All results are from Linux x86_64 + pluginval. The code uses only portable JUCE / C++20, but nothing here proves it loads, scans or behaves in Ableton Live. Treat the Windows build as unverified until `CONTINUATION.md` step list is done.
2. The Steinberg VST3 validator was not run (pluginval skipped that step). pluginval passing is not a certification.
3. macOS and AU are not targets and were not built.
4. Drag-and-drop of audio to a DAW (`performExternalDragDropOfFiles`) produces real temporary WAV files (tested) but whether a given host accepts the drop was not tested (no host available). Use the Export buttons as the reliable path.

## Single-plug-in design
0. DaliCandy is one VST3 (`Instrument|Synth|Fx`). It works as an effect while its main audio input is connected and as an instrument otherwise. Whether Ableton Live (or another host) shows such a plug-in on both instrument and audio tracks, and whether it feeds audio into the input of a plug-in flagged as an instrument, **is host behaviour that I could not test**. The split two-plug-in build is still available as `-DDALI_BUILD_INSTRUMENT=ON -DDALI_BUILD_FX=ON`.

## GUI
5. The GUI was verified by headless snapshots, pluginval's editor tests and a scripted smoke test, not by a person using a mouse. Layout was only looked at at 1280x820; it is resizable (1040x700 to 1900x1200) but no HiDPI scaling check was made.
6. No undo / redo for sound edits (use Recall / history and presets).
7. The MSEG editor has at most 8 points; the custom LFO curve has 16 points; modulation destinations are chosen from a flat list.

## Audio / DSP
8. **Level varies with sample rate for some resonant material.** Resonator and Glitch were normalised across 44.1-96 kHz, but a remaining outlier (a metallic "Bell Ping"-type sound) differs by up to about 6 dB between 44.1 kHz and 96 kHz. Export tests only assert `peak <= 0 dBFS`. Sounds generated at one rate and played at another can therefore differ in loudness; the output protector prevents overs but does not equalise.
9. The generator renders previews at <= 48 kHz; candidates are judged there.
10. Negative Space is applied (a) when the pattern is planned from an analysis and (b) as a live "leave out non-frozen events" probability in the FX while the incoming audio is busy. It does not look ahead in time; it cannot know what the track will do next.
11. Psychoacoustic masking is a band-occupancy **estimate**; it cannot guarantee a sound will or will not be masked. The adaptive actions are deliberately conservative (low cut, one dynamic EQ band, width, trim).
12. Capture needs host transport and a connected audio input (or sidechain). On an instrument track the audio input is off; use Import WAV there. Imported audio is analysed as mono, only the first 32 bars are used, and it assumes the BPM set in *Track BPM* and 4/4 for the grid.
13. Polyphony is bounded: 8 concurrent candy events, 4 layers each; the oldest event is stolen. Intentional (CPU safety), but dense MIDI playing will steal.
14. The tail length reported to the host is a fixed 6 s.
15. The taste model is a simple weighted-feature preference model (transparent, local), not a trained neural model; it needs a dozen or so ratings before it visibly steers results.
16. MIDI export writes one loop pass of the pattern (probabilistic events use loop index 0).

## Presets
17. Preset format v1 was a development prototype; it migrates on load but the migration only has synthetic test files behind it.
18. The 56 factory presets were generated by `DaliCandyBankTool` and checked for validity and audibility by tests; they were not hand-tuned or listened to by a human.

## Kitchen
19. **Fusions and families are not hand-designed sounds.** A family is a fixed grouping of the existing 34 archetypes (SWIRL = Psychedelic + Experimental, HAZE = Atmospheric + Transitions); a fusion layers one archetype of each family and re-routes modulation. Tests check validity, determinism, loudness window and that both halves contribute layers; **whether every one of the 15 fusions sounds good is a matter of taste and was not judged by a human.** Some pairs (e.g. two long families) produce busy results.
20. **Synced length is a fit, not a guarantee of sound.** Generation tunes envelopes and tails until the audible length is 50-130 % of the window and rejects candidates that cannot be fitted (about one in five attempts is rejected at 1/16 and some sounds are simply not available at very short or very long windows). The dragged / exported one-shot is cut or padded to *exactly* the window, so long windows of short sounds contain silence (or delay echoes the fit added). Time signature is assumed 4/4; the tempo is the host tempo at the moment of generation / drag.
21. DRIFT, Length, KEEP and LISTEN are plug-in parameters stored in the host session, **not** in `.dalicandy` presets; presets store family, fusion and spice together with the generate settings. Loading a preset does not change them.
22. LISTEN steering uses the lowest *average* band level between 400 Hz and 12 kHz of the captured audio; it is a simple gap finder, not a model of what is musically missing. On an instrument track (no audio input) LISTEN cannot capture; use *Import WAV* in Track analysis, then generate with the *Listen* parameter on.
23. ROLL is random by design (seeded from the clock); two ROLLs never repeat, but `rollWith(seed)` is reproducible (tested).
24. The on-screen keyboard, flavour matrix, drag pads and plates were exercised only headlessly (snapshots, smoke test); no human has clicked them in a real host.

## Process
19. ASan + UBSan + LeakSanitizer were run over the test runner (clean); no TSan, and no sanitizer pass over the plug-in binary or GUI. Threading is covered by a concurrent-edit stress test and the allocation-free `processBlock` test.
20. The CPU figures come from a shared 2-core container; worst-block spikes of 10-48 % were seen between runs and not diagnosed.
